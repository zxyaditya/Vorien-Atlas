# Atlas — Architectural Decision Records (ADRs)

> Every important architectural decision that has shaped Atlas.
> New AI sessions must read this before proposing changes that touch the ground rules.

---

## DEC-001 — Two-tier product split: Atlas Core + Decision Engine
- **Date**: Session 1 / v0.1
- **Decision**: `atlas_core/` implements Book 1 Layers 1–4 as a pure Python library; `decision_engine/` implements Layer 5.
- **Rationale**: Structurally prevents L5 concerns from leaking into Atlas Core.
- **Status**: Permanent.

## DEC-002 — Rename Book 1's "Subsystem" to "Perspective"
- **Date**: Session 1 / v0.1
- **Decision**: Rename the 11 mathematical question-classes to Perspectives.
- **Status**: Permanent.

## DEC-003 — Silent SHA-1 formula-hash Rule-1 guardrail
- **Date**: Session 2 / v0.2
- **Decision**: On every register, compute `sha1(formula + params)`. Reject duplicates.
- **Status**: Permanent.

## DEC-004 — ML lives outside Atlas Core (Invariant 5.6)

## DEC-005 — Market Structure at L2, Cross-Asset deferred to L4

## DEC-017 — Learning System as L5 Sibling
- **Date**: v0.10.0
- **Decision**: The Learning System (handling datasets, models, training, evaluation, registry, inference) lives at `/app/backend/learning_system/` as a peer to the Decision Engine, completely separate from it.
- **Rationale**: Isolates stateful ML lifecycle components from the deterministic rule-based Voter. Prevents ML logic from bleeding into core decision-making.

## DEC-018 — Purged K-Fold with Embargo
- **Date**: v0.10.0
- **Decision**: The model plug-in contract natively incorporates purged K-Fold cross-validation with embargo zones.
- **Rationale**: Standard K-Fold leaks future information due to serial correlation in financial time series. Purging and embargoing strictly isolate the training and validation distributions, ensuring mathematically rigorous backtesting.

## DEC-019 — Regime-Conditional Triple Barrier Labeling
- **Date**: v0.11.0
- **Decision**: Replaced static take-profit/stop-loss labeling with Regime-Conditional Triple Barrier Labeling, where dynamic thresholds are generated by L3 regime states.
- **Rationale**: Standard barriers suffer from fixed-width assumptions that fail across shifting volatility environments. Regime-conditional barriers adapt the hitting constraints based on the measured L3 context.

## DEC-020 — LiveExecutionEngine Broker Adapter Pattern
- **Date**: v0.13.0
- **Decision**: Created the `BrokerAdapter` interface for `LiveExecutionEngine` (currently implemented by a Simulated stub) mapping uniform engine commands to abstract broker endpoints.
- **Rationale**: Provides a seamless transition from backtesting to live deployment. Strategies run identically on paper and live instances, bounded by the broker adapter.

## DEC-021 — BacktestTracker Pagination
- **Date**: v1.0.0
- **Decision**: The BacktestTracker strictly paginates metadata lists, intentionally excluding the heavy `trades` and `equity` arrays from summary fetches. Full results are loaded on demand via targeted API endpoints.
- **Rationale**: Memory exhaustion when requesting the full backtest registry. Excluding heavy arrays ensures sub-10ms response times for the Learning Tab UI.
